# オクトラ1 自動レベル・JP稼ぎ

WindowsのSteam版向けの初期版です。ゲームのメモリやセーブデータは編集せず、ゲーム画面の一部分と登録した見本を比較し、キーボード操作を送ります。普段の操作はコントローラーのままで使えます。ゲーム側がキーボード入力を受け付ける必要があります。

## 起動

`start.bat` をダブルクリック。Python 3.10以降、Pillow、NumPy、OpenCVが必要です。このPCでは導入済みを確認しています。不足するPCでは `python -m pip install -r requirements.txt` で導入してください。

## 初回設定

メイン画面は408×520の小型パネルです。「◆固定」で最前面表示を切り替えられ、設定は次回起動にも保存されます。キーや時間は「操作設定」、見本は「画像登録」、HPの基準は「回復設定」から変更します。設定画面を開くと周回を停止します。最前面表示中はゲームのウィンドウ自体から画像を取得し、パネルの重なりを判定画像に含めません。F8・F9の操作は従来どおりです。

1. ゲームをウィンドウまたはボーダーレス表示にする。ほかのウィンドウをゲームに重ねない。登録後は解像度を変えない。
2. ゲームのキーボード設定を確認し、ツールの「左へ移動」「右へ移動」「決定キー」を合わせる。既定値は仮設定です。コントローラーを触らずに、その3キーがゲームで動くか手動で確認する。
3. 通常攻撃の繰り返しで安定して勝てる敵のいる場所へ手動で移動する。HPを回復しておき、出入口・宝箱・NPC・段差のない平らな場所を選ぶ。往復は出発点に戻る保証はありません。
4. 「フィールド」を選び「見本を追加」を押し、5秒以内にゲームを前面にする。撮影後、**ミニマップ中央の小さな丸印**を、周囲2〜3pxの余白を含めて囲んで登録する。景色・キャラ・ミニマップ全体は囲まない。中央印の見本を周辺から探すため、1280×720なら上下左右16pxまでのずれに対応する（高解像度では探索範囲も拡大）。明るさの平均差を除いて比較するが、拡大率の変更や大きな変形には対応しない。以前の版で景色を登録していた場合は「フィールド」を消して登録し直す。
5. 手動で戦闘に入り「戦闘」の見本を登録する。コマンド選択中・敵の選択中・演出中でも残る、戦闘固有の固定HUDを選ぶ。「たたかう」だけだと敵の選択時に消えて停止する可能性があります。必要なら異なる状態の見本を複数追加する。
6. 手動で勝利し「勝利結果」の見本を登録する。獲得EXP・JPの数値ではなく、固定の見出しなどを選ぶ。結果画面に段階がある場合は、それぞれ登録する。
   レベルアップ時だけ止まる場合は「レベルアップ」を選び、その画面固有の「Level Up」などの固定文字を追加登録する。通常結果とレベルアップは同じ結果画面として扱い、どちらも決定キーで進める。複数人が順にレベルアップする場合は必要な見本を追加する。結果画面全体での30秒の上限は共通で、勝利数は1回だけ数える。
7. 各画面で「判定テスト」を行う。差が小さいほど見本に似ています。想定外の画面でも一致する場合は、見本を消して選び直す。許容差を大きくすると誤判定しやすくなります。
8. 「判定のみ」にチェックしたまま開始し、手動で1戦する。画面ごとの判定が切り替わるか確認する。
9. チェックを外し、実行上限をまず60秒程度にしてフィールドから開始する。5秒以内にゲームを前面にする。F9でいつでも停止できることも確認する。

アプリを起動しておけば、**F8で即開始・停止**できます。画面を切り替える必要はありません。F9は緊急停止です。通常モードではゲームが前面である必要があります。バックグラウンド動作を有効にすると、ほかの窓が前面でもF8で開始できます。アプリの開始ボタンには5秒の猶予があります。フィールドのほか、登録済みの戦闘・勝利結果・レベルアップ画面からも再開できます。「不明」や停止画面からは開始しません。起動しただけでは自動操作を始めません。

「判定のみ」のON/OFFは変更時に保存し、次回起動時にも復元します。「キー送信：ON」は開始後に実際に操作する設定、「OFF」は画面判定だけ行う設定です。起動しただけでは操作を開始しません。実行中や開始待ちにモードを切り替えた場合は停止するため、もう一度「開始」を押してください。

## バックグラウンド動作

「バックグラウンド動作」にチェックを入れると、非アクティブでも動作します。ゲームに他の窓を重ねても構いません。ウィンドウ表示またはボーダーレスで使い、**ゲーム自体は最小化しないでください**。最小化・ゲーム終了時は停止します。設定は次回起動時にも復元します。

このモードはゲームのHWNDだけにキーの押下・解放通知を送り、通常モードのSendInputへは切り替えません。画面はデスクトップの切り抜きではなく、対象ウィンドウから取得します。画像取得は別スレッドで行い、2秒以上更新されない場合は停止します。F9による停止は画像取得とは別に監視します。

このPCの実機で非アクティブ中の方向入力と、他の窓に隠れたゲーム画面の取得を確認しています。OS・ゲーム更新や表示モードによっては動作が変わる可能性があります。通常モードに戻すにはチェックを外してください。

BPモード追加時の実機確認では、非アクティブのままBP投入・戦闘・勝利・フィールド復帰を含む2戦を確認しています。状態の切り替わり、BPの読み取り、停止理由は `profiles/runtime.log` に保存します。ファイルは最大約1MB×2個に制限しています。`background_probe.py` は対象ゲームへの1回の方向入力とウィンドウ画像取得を手動で試す診断用ツールで、通常利用では起動不要です。

## BPモード（全投入）

「BP全投入」を有効にすると、戦闘扱いの間は **ブーストキー3回 → 決定キー2回** を繰り返します。ブーストキーの既定値は `o`、決定は `enter` です。残りBPの数、行動中のキャラ、BPが減ったかどうかは入力条件にしません。BP読取やコマンド表示を待ってEnterを抑止する処理、使用条件1/2/3の選択は廃止しました。

各キーの送信間隔は最短0.1秒で、キーを押してから離す操作を繰り返します。BPが足りない分や演出中などゲームが受け付けない入力は、そのまま次のキーへ進みます。入力受付とのタイミングによって、必ず全ターンで全BPを使い切れることまでは保証しません。ゲームの1行動当たりのブースト上限を超えてBPを使う機能ではありません。フィールド・勝利結果・停止画面ではこの繰り返しをやめ、それぞれの操作へ切り替えます。

「Boost」の表示は戦闘画面の補助判定に使いますが、認識できなくても全投入のキー列を止めません。弱点や敵HP、スキルの最適化は行いません。

## 簡易判定

「簡易判定」は、フィールドなら移動、登録済みの勝利結果なら決定＋回数記録、それ以外なら戦闘扱いで決定を送ります。停止画面は最優先で、真っ黒な遷移画像では入力を待ちます。戦闘の見本は必須ではなくなります。BPモードでは戦闘扱いの間、ブースト3回と決定2回を繰り返します。**メニューにも決定を送るため、手動でメニューを開く前にF8で停止してください。** フィールドを認識できないとフィールド上でも決定を送るため、フィールド判定は引き続き必要です。

## 戦闘後HP回復

「戦闘後HP回復」を有効にすると、戦闘からフィールドへ戻った際、移動を始める前にメニューを開いて全員のHPバーを確認します。既定では**誰かがHP60%未満なら、オフィーリアの「回復魔法」で全体回復**します。現在の4人編成と日本語UIに合わせて設定しています。HPの判定は数字のOCRではなくHPバーの長さの概算です。

HPが基準以上なら回復を使わず、そのままフィールドへ戻ります。回復を使った場合は実際にHPが増えたことと全員が基準以上になったことを確認してから戻り、周回を再開します。回復中は通常の移動・BP・Enter連打を止め、各画面のカーソルと見出しを確認して操作します。

「回復設定」で基準割合・編成人数・メニューキー・戻るキーを変更できます。既定は60%、4人、メニュー `i`、戻る `backspace` です。編成の人数を変更した場合は人数設定も合わせてください。オフィーリアの「回復魔法」を確認できない編成では停止します。回復量の大きい別アビリティ、アイテム回復、SP自動補充、蘇生は実装していません。

「HP確認・回復テスト」はフィールドから一度だけHP確認・必要時の回復・フィールド復帰を実行して停止します。既定の消費SPは実画面で8と確認しています。SP不足などでメニューが進まない・回復後にHPが増えない・HP0・HPを読み取れない・3回使っても基準未満の場合は停止します。処理全体の上限は35秒です。失敗時にメニューが残っている場合は原因を確認し、手動でフィールドへ戻してからF8で再開してください。F9は回復中も使用できます。

実機では、全員が基準以上のときにSPを使わずフィールドへ戻るテストと、非アクティブで戦闘後にHPバー約50%を検出→回復魔法1回→約71%への増加確認→フィールド復帰→周回再開を確認しています。

## 現在の機能と制限

- フィールドで左右に往復 → 戦闘で決定を一定間隔で入力 → 勝利画面を閉じる、の繰り返し。各キャラが通常攻撃を選択できるメニュー状態で使用してください。スキル選択や対象の最適化はありません。
- ダッシュキーは既定で `lshift`（左Shift）です。フィールド移動中だけ方向キーと同時に押し、戦闘・判定待ち・停止時には解放します。ゲーム側で別のキーを割り当てている場合は合わせてください。ダッシュを使わない場合は `none` を選びます。
- 決定の間隔は既定0.15秒、設定範囲は0.1〜5秒です。速すぎてゲームが入力を受け取れない場合は0.2〜0.3秒程度に戻してください。ゲーム内のアニメーション自体を短縮する機能ではありません。
- キー解放、F9、前面ウィンドウの確認は約20msごと、画像判定は約80msごとです。決定キーは約40ms押してから解放します。画面取得・認識処理とゲーム側の処理時間によって、実際の間隔は長くなる場合があります。
- 判定不能中はキーを解放し、20秒続くと停止。通常モードは前面変更でも停止。解像度変更・上限時間・バックグラウンド時の最小化でも停止。戦闘は既定180秒、遭遇なしは120秒、結果画面は30秒で停止します。
- 画面認識は簡易的な画像比較です。誤判定を完全には防げません。戦闘中の回復・全滅の自動検知・EXP/JP数値の集計は未実装です。「停止画面」を任意で登録できますが、その見本に一致した場合だけ停止します。
- フィールドは位置ずれを許容した明暗パターンの比較、ほかの画面は登録位置の色比較を使うため、判定テストの「差」は画面の種類をまたいで厳密に比較できる値ではありません。ミニマップを非表示にするとフィールド判定ができません。
- フィールドでは半透明のミニマップ越しに見える景色の影響を減らすため、緩やかな明暗を除いてから中央印を比較します。判定の差が許容差を超えたとき、または複数画面の判定が競合したときは「不明」になります。許容差を大きくする前に、中央印以外を広く囲んでいないか確認してください。
- 勝利数は戦闘判定後に勝利画面を検出した回数です。EXP/JPが入ったことを保証する計測ではありません。
- 見本と設定は `profiles/` にローカル保存します。見本の登録解除は設定から外す操作で、PNG自体は残ります。通信・アップロードは行いません。
- コントローラーを操作するとメニュー選択や歩く方向が変わるため、自動操作中は触らないでください。
- OSの入力制限やゲームの入力処理によってキー送信が届かない場合があります。実機での周回動作は別途確認が必要です。

`python -m unittest discover -s tests -v`

テストでは実際のゲームへキーを送信しません。
